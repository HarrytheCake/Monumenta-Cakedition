# CakeMonu: agent reference

Client-only mod (`cakemonu`, package `io.github.harrythecake.cakemonu`), started 2026-11-23. Home for Monumenta helpers that **bridge other mods**. Built on the Cake multiloader kit (`tools/multiloader/README.md` in the Cakedition repo) but **only Fabric 1.20.4 exists for now** (user, 2026-11-23: "keep the road for future multiloader/version, but for now just do fabric 1.20.4"): `core/` + `1.20.4/common` + `1.20.4/fabric`. Another version or NeoForge = add the folder (`apply_kit.py cakemonu <mc>`). **License GPL-3.0-or-later** (it hooks into UMM, GPL-3.0); the other Cake mods stay MIT, so never move CakeMonu code into them or theirs into it without that in mind. Not in the pack yet; no mirror/repo yet (would be `HarrytheCake/CakeMonu`).

## Feature 1: UMM ability icons on their own

Decisions (user, 2026-11-23): separate bridge mod (not inside CakeUI, not a UMM fork); name CakeMonu; picking = per-ability "Own place" switches in CakeMonu's screen + CakeUI's HUD editor to move/resize (UMM's bar stays one CakeUI movable); saved **per ability** (UMM's `AbilityInfo.getOrderId()` = `class/name` lower case, so each class has its own layout); **CakeUI optional**.

How it works:
- `fabric/mixin/AbilitiesHudMixin` (on UMM's `hud.AbilitiesHud`, `remap = false`): `isAbilityVisible` HEAD → `UmmAbilities.visibility(id, forSpace)`: normally a placed ability = false (left out of the bar, the bar closes up, its box/clicks/tooltips follow because UMM filters by this method everywhere); while `solo` is set, only that ability is visible (`forSpace` true, the rest UMM's own answer, so show-only-on-cooldown etc. still apply). `isEnabled` RETURN → false when every current ability is placed (empty bar takes no clicks).
- `fabric/mixin/AbilitiesHudInvoker`: UMM's protected `render(GuiGraphics, float)`. `UmmAbilities.drawPlaced` (Fabric `HudRenderCallback`): for each placed ability of the current class: push pose, translate to its box, scale = box size / UMM's icon size, `solo = id`, call UMM's render (one visible ability → drawn at 0,0), pop. So UMM draws cooldown overlay, flash, charges, duration bar/circle, silence, text exactly as in its bar. An exception switches drawing off until restart (logged).
- **Version gate:** `UmmSupport.SUPPORTED = {"1.10"}`; `UmmMixinPlugin` applies the mixins only for those versions, `CakeMonuFabric` installs `UmmAbilities` only then; otherwise a `Missing` source (state NO_UMM / UNSUPPORTED, the screen says so). **After a UMM update: read its `AbilitiesHud` (render loop, isAbilityVisible, isEnabled, getTotalSize) and add the version.** UMM's source: github.com/Njol/UnofficialMonumentaMod branch `mc1.20.4` (Ascynx's fork has unreleased 1.20.4 fixes, no release).
- **UMM's bundled UI library** (`ch.njol.minecraft.uiframework`, nested jar) isn't on Loom's compile classpath: never use an `AbilitiesHud` value as its own type in a way javac must check against its superclass `HudElement` (method calls, `getClass()`, casts from it). `UmmAbilities` holds it as `Object`; `getDimension()` (the bar box) is called by reflection.
- core: `IconPlacement` (9 anchors by thirds of the screen, offset from the anchor point, size 0 = follow UMM, 8–128; `fromBox` = editor drop; `nextTo` = first place after the bar / below a column, skipping taken spots, kept on screen), `IconLayout` (`config/cakemonu/ability-icons.json`, format 1; unreadable/newer file → moved to `.broken`, starts empty), `AbilitySource` (what the bridge provides), `CakeMonu` (layout + source, `setPlaced`, `clearAll`, `load`/`save`).
- common: `SettingsScreen` (rows of current abilities + placed ones of other classes, "Own place" switch each, Edit HUD… / All back to the bar / Done; scrolls by rows), `CakeMonuPlugin` (`cakeui` entrypoint: `addMovables`, one `IconMovable` per placed current ability, id `ability/<id>`, resizable; Cancel re-reads the file), `CakeUIBridge` (CakeUI classes only after the plugin ran), `ConfigReload` (`cakeconfighub:reload` + `/cakemonu reload`).
- fabric: `CakeMonuFabric` (entrypoint, `/cakemonu` opens the screen via `mc.tell` after chat closes), `ModMenuEntry`, `FabricPlatform`.
- Depends on Fabric API (commands, HUD callback; UMM needs it anyway). Suggests UMM 1.10 and CakeUI ≥ 0.3.0. Compile-only deps in `gradle/cakemonu.gradle`: UMM from Modrinth maven (`umm_version=mbs17xsz`), CakeUI release jars (Ivy, `-Pcakeui_dir=` for a local build).
- Lang en_us, zh_cn, zh_tw (same keys).

Not done / ideas: tooltip (ability name) on a placed icon while the chat is open (UMM's tooltip only covers its bar); UMM's own drag-to-reorder in the chat screen indexes the unfiltered list (UMM's bug, present before CakeMonu); CakeConfighub map not needed (the file is per-player state, no settings).
